# Repository Guidelines

## Project Structure & Module Organization

- `flake.nix` defines supported systems and Home Manager configurations.
- `home.nix` contains shared packages, Fish configuration, themes, session variables, and activation hooks.
- `bootstrap.sh` detects the host, generates local machine settings, validates the flake, and applies Home Manager.
- `machine.nix` is generated by `bootstrap.sh` and intentionally ignored by Git. Do not commit machine-specific usernames or home directories.
- `flake.lock` pins all flake inputs and should be committed whenever dependencies change.

This repository currently has no separate test or asset directories. Keep reusable configuration in `home.nix`; add focused modules when a feature becomes large enough to maintain independently.

## Build, Test, and Development Commands

```sh
./bootstrap.sh
```

Generates `machine.nix`, checks the flake, and activates the configuration for the detected platform.

```sh
nix --extra-experimental-features "nix-command flakes" flake check path:.
```

Evaluates all declared Home Manager outputs without activating them. Use `path:.` because the flake imports the ignored, generated `machine.nix`.

```sh
home-manager switch --flake "path:.#aarch64-darwin"
```

Applies a specific configuration. Replace the system attribute when testing Linux. After Fish configuration changes, start a new shell with `exec fish -l`.

## Coding Style & Naming Conventions

Follow the surrounding Nix layout: one attribute per line, trailing semicolons, descriptive camelCase local names, and quoted multiline shell blocks. Keep Bash compatible with `set -euo pipefail`, quote expansions, and use lowercase snake_case variables. No formatter or linter is configured, so avoid unrelated formatting churn.

## Testing Guidelines

There is no unit-test framework or coverage target. Every change must pass `flake check path:.`. For activation hooks or Fish changes, apply the configuration and verify the affected command in a fresh shell. Test platform-specific branches on their target OS when possible.

## Commit & Pull Request Guidelines

The repository has no commit history yet. Use short, imperative subjects, optionally with a conventional prefix, such as `fix: load Nix environment in Fish`. Keep dependency-lock changes with the configuration that requires them.

Pull requests should explain the motivation, list affected platforms, note generated or activation behavior, and include the exact validation commands run. Link relevant issues and call out any required manual system changes.
